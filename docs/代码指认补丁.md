# 答辩补丁 · 三处关键代码的指认说法

> 考查要求：「打开仓库，能指认 2～3 处自己写的关键代码」。讲稿里只有 P6 一带而过，这三条补上。
> 每处都写成：**在哪 → 它做什么 → 为什么这么写 → 可能被问什么**。

## 第一处 · `tools.py` 的 `WheelEngine`（约 118–170 行）

**怎么打开**：仓库根目录 → `tools.py` → 搜 `class WheelEngine`

**它做什么**

```python
def probabilities(self, layer, options):
    w = self._ensure(layer, options)
    total = sum(w.values())
    return {o: round(w[o] / total, 4) for o in options}

def reject(self, layer, item):
    self.weights[layer][item] = 0.0   # 本会话内清零，永不复活
```

**为什么这么写**：转盘的扇区面积不是画上去的，是这里算出来再画的。三个动作构成闭环——抽中衰减 `decay`、拒绝清零 `reject`、每次读取重新归一化 `probabilities`。所以「拒掉一个，剩下的概率变大」是真的数学结果，不是动画效果。

**可能被问**：*「拒绝几次之后会不会只剩一个？」*
答：会，而且这是设计。全拒完就说明这一层没有想要的，应该退回上一层重新起盘，而不是继续陪转。

## 第二处 · `agent.py` 的 `chat()`（约 210–310 行）与 `scoped_tools()`（96 行）

**怎么打开**：`agent.py` → 搜 `def chat` 和 `def scoped_tools`

**它做什么**：模型返回 `tool_calls` 之后，由这里执行工具并把结果塞回消息，再进下一轮；`scoped_tools(scope)` 按当前层限定这一轮只暴露哪几个工具。

**为什么这么写**：这是全场最该讲的设计选择——**模型只负责听懂，流程由状态机决定**。如果不给 `scope`，模型可能在第 2 层就去调 `build_wheel('dish')`，跳层；限定了工具集，它只能在合法的那几个里选。

**可能被问**：*「这和让模型自己规划有什么区别？」*
答：自主规划适合开放性任务；这里五层是确定的，让模型规划只会走偏。我宁可把自由度收窄，换取可复现。这也是 Q7 不用 LangChain 的同一个理由。

## 第三处 · `tools.py` 的 `dish_key()`（56 行）与 `_display_name()`（70 行）

**怎么打开**：`tools.py` → 搜 `def dish_key`

**它做什么**：把不同店卖的同一道菜归成一个 key，展示时用 `_display_name` 把成员店名拼出来（如「2 家都有 · ¥14 起」）。

**为什么这么写**：不做这个，174 个候选里有大量重复菜，同一道菜占三个格子，用户会以为选项很多其实没得选。归一之后「选项数量」才等于「真实可选项数量」——这条直接支撑台上那句「别人给你更多选项，我帮你减少选项」。

**可能被问**：*「归一规则错了怎么办？」*
答：规则是显式写死的（菜名去空格/统一异体字/按主料归并），错了能改、能测；用模型去判同一道菜反而不可复现。
