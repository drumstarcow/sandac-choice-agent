03 · 核心机制

把「选择」拆成五次抛硬币。

174 个候选一个都不截断。之前按评分只留前 24 个，等于偷偷删掉了 86% 的选项。
🚫 可拒绝

🎯 元选项不上盘
「随便」不是一个能被抽中的结果，是「这层我不要了」的操作 —— 所以它站在盘外，不占扇区。
03 · 核心机制04 / 12
04 · 它长什么样

转一下，就是一下。

第 0 层 · 餐别 —— 两个扇区各 50%，百分比是后端算的真实权重。 三个按钮全在盘外：「就要这个」「换一个（拒绝）」「都行，你替我定」—— 盘上只放能被抽中的真选项。
第 4 层 · 菜品 —— 格子跳动 28～44 次后减速停下，停下的那格放大成名片。 同一道菜只占一格：两家都在卖的「麻辣烫」合成一格，标「2 家都有 · ¥14 起」。
04 · 界面05 / 12
05 · 关键代码（我自己写的）

概率不是动画，是算出来的。

class WheelEngine:
    """真实权重概率模型：抽中衰减 / 拒绝清零 / 归一化"""
    DECAY = 0.6              # 抽中后衰减，避免连着抽同一个

    def probabilities(self, layer, options):
        w = self._ensure(layer, options)
        total = sum(w.values())
        return {o: round(w[o] / total, 4) for o in options}

    def reject(self, layer, item):
        # 拒绝：本次会话内权重清零，永不复活
        self.weights[layer][item] = 0.0

    def decay(self, layer, item):
        self.weights[layer][item] *= self.DECAY

1
权重存在后端，不在前端
前端只负责画。扇区上那个百分比，是把后端算出来的数直接显示 —— 所以拒绝之后它会变，而且不重播动画也会变。
2
模型读的是结构化 tool_calls
不是解析「🔧」这种字符串。日志里 tool_calls=1 是从 resp.choices[0].message.tool_calls 里数出来的。
3
关键词只在模型挂了才兜底
异常或返回空时才会走关键词分支，并打上黄色「兜底模式」标签 —— 正常演示里这个标签不该出现。
