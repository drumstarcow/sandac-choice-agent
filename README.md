# 🎡 杉达选择助手 · 今天吃啥大转盘

> **开源创新微专业 · 期末考查（路径 B：校园服务智能体）**
> 一个专门帮“选择困难”的大学生做吃饭决策的智能体：**自然语言理解 → 真实 Tool Calling → 决策大转盘 → 美食名片 → 确定产出**。

---

## 一、项目简介

很多大学生都有“选择困难”：站在食堂门口不知道吃啥、想吃点辣又怕踩雷。本项目把“帮人做选择”作为智能体的核心价值，做成一套**决策大转盘**交互：

- **第一层 · 在哪吃**：食堂 / 外卖 / 外面吃
- **第二层 · 口味**：辣 / 不辣 / **随便**（无所谓就选它，第三层不过滤）
- **第三层 · 菜品**：所有菜品（按口味过滤；「随便」则全量）。随机转到不想要的 → **拒绝** → 剔除选项 → 重新排转盘（剩余选项概率自动均分）
- **确定前 · 美食名片**：弹出一张带美食特写与介绍的卡片勾起食欲；不喜欢可「换一个」回到第三层重转
- **确定后**：生成「今日决定」产出物（Markdown 文件），可一键发给室友（**危险操作，需确认**）

> 设计要点：不是“啥都答的豆包”，而是**专精于“吃饭决策”这一个领域**；转盘选项来自真实数据文件，被拒绝后概率均分重排——是真实的“决策辅助”，不是关键词 if-else。

## 三、技术栈

- **语言**：Python 3（标准库 `urllib` 调用模型，**零第三方依赖**，离线可跑）
- **模型**：本地 Ollama，`buding-qwen05b-32k`（0.5B，离线、免 Key）；亦可在 `.env` 切换为百炼/OpenAI 兼容端点
- **界面**：Streamlit（`app.py`）；终端（`cli.py`）；独立动画版 HTML+Canvas（`wheel.html`，双击即开）
- **数据源**：`data/food_data.json`（示例数据，字段与真实校园数据一致，替换即真实可用）

## 五、环境要求与运行

### 1. 安装并启动本地模型（只需一次）
```powershell
# 安装 Ollama（Windows）：https://ollama.com 下载安装，或
winget install Ollama.Ollama

# 拉取并启动模型（示例用 0.5B 本地模型，离线可用）
ollama pull buding-qwen05b-32k
ollama serve        # 默认监听 http://localhost:11434
```

### 2. 运行 Streamlit 界面（推荐演示入口）
```powershell
cd <项目目录>
pip install -r requirements.txt
python -m streamlit run app.py
# 浏览器打开终端给出的 http://localhost:8501
```

### 3. 运行终端演示（备用）
```powershell
python cli.py
```

### 4. 独立动画版大转盘（最直观，双击即开）
直接用浏览器打开 `wheel.html` 即可，无需启动任何服务；可选联网调用本地 Ollama 生成一句“勾食欲”的解说。

### 5. 切换为联网大模型（可选）
复制 `.env.example` 为 `.env`，修改 `OLLAMA_MODEL` 为百炼/OpenAI 兼容模型，并设置 `OPENAI_API_KEY` 与 `BASE_URL`。

## 六、演示话术（上台参考）

1. **开场**：“很多同学都有选择困难，今天我做一个专门帮大家做吃饭决策的智能体。”
2. **触发**：“不知道今天吃啥，帮我选选。”（→ 模型调用 `build_wheel(where)`，弹出第一层转盘）
3. **第一层**：点「转一下」→ 指向「食堂」→「接受」。
4. **第二层**：口味转盘 →「不辣」→「接受」。
5. **第三层**：菜品转盘 → 转到「麻辣香锅」→「拒绝」→ 剔除后重转（演示概率均分）→ 转到「番茄炒蛋」→「接受」。
6. **美食名片**：弹出卡片，介绍与价格 →「就吃这个，确定」。
7. **产出物**：生成「今日决定.md」，可下载；演示「发给室友」→ 弹出**确认**框（危险操作不执行）。
8. **收尾**：“这就是一个专精于吃饭决策的智能体：真实 Tool Calling、可交互转盘、危险操作有确认。”

## 七、数据说明（如何从“示例”变“真实”）

`data/food_data.json` 当前为**示例数据**，字段结构（`where_options` / `spice_options` 内置 / `dishes[]` 含 name,price,canteen,window,tags,desc）与真实食堂数据一致。只需把各字段替换为上海杉达学院食堂**真实的窗口/菜品/价格/标签**，本助手即成为真实数据源——无需改动任何代码。

> 关于“假数据”的说明：智能体的价值永远来自背后的真实系统。本作业按课程“路径 B 允许模拟后端”的约定，使用标注清楚的示例数据演示完整工具调用与设计；架构已为接入真实数据源预留（替换 JSON 即可），符合工程实践。

## 九、局限与改进

- 当前菜品数据为示例；接入杉达真实菜单后实用性更强。
- 0.5B 本地模型在“多级工具链”上偶有不稳定的情况，演示时由界面状态机保证每一层转盘都正确（LLM 负责理解与开场触发+解说）。可换更大模型进一步提升自主链式调用能力。
- 后续可扩展更多决策场景（去哪自习、周末去哪玩），复用同一套转盘机制。
