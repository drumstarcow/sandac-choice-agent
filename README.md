# 🎡 杉达选择助手 · 帮我做选择（校园决策智能体）

> **开源创新微专业 · 期末考查（路径 B：校园服务智能体）**
> 一个专门帮“选择困难”的大学生做吃饭决策的智能体：**自然语言理解 → 真实 Tool Calling → 决策大转盘 / 就近性价比推荐 → 记忆画像 → 确定产出**。

---

## 一、项目简介

很多大学生都有“选择困难”：站在食堂门口不知道吃啥、想吃点辣又怕踩雷、想出去吃又不知道附近哪家性价比高。本项目把“**帮大学生做选择**”作为智能体的核心价值，做成两路能力：

**能力一 · 决策大转盘**（不知道吃啥、想玩一下时用）
- **第一层 · 在哪吃**：食堂 / 外卖 / 外面吃
- **第二层 · 口味**：辣 / 不辣 / **随便**（无所谓就选它，第三层不过滤）
- **第三层 · 菜品**：按口味过滤；转盘可设**金额上限**；随机转到不想要的 → **拒绝** → 剔除 → 重排（剩余概率自动均分）
- **确定前 · 美食名片**：弹出特写+介绍的卡片勾起食欲；不喜欢可「换一个」重转
- **确定后**：生成「今日决定」产出物（Markdown），可一键发给室友（**危险操作，需确认**）

**能力二 · 就近综合推荐**（心里已有想法、要“直接给方案”时用）
- 以你定位的**校区为圆心**（如「上海杉达金海校区」），用 haversine **真实算距离**
- 按 **距离 + 性价比 + 评分** 加权排序，给出就近美食清单
- 显示：**店名 / 位置 / 距离 / 预估花销 / 评分 / 综合分**，可切换「性价比综合 / 就近优先 / 好评优先」
- 转盘上可设**金额上限 / 不限**；用户不想转盘时直接给**最佳性价比方案**

**记忆能力（智能体的“牙齿”）**
- **用户记忆画像**（`data/profile.json`，本地持久化）：记住校区(定位圆心)/金额上限/口味偏好/忌口/饮食限制，跨轮套用
- **选择历史 + 近期画像**：每次完成选择都留痕（`data/history.json`）；最近 10 次聚合出“近期画像”（最常去校区/场景/口味、最爱菜或店、平均预算与花销）——用户可查看历史、删除不想要的

> 设计要点：不是“啥都答的豆包”，而是**专精于“吃饭决策”这一个领域**；转盘与推荐都来自真实数据+真实计算，被拒绝后概率均分重排、距离用球面公式实时算——是真实的“决策辅助”，不是关键词 if-else。

## 三、技术栈

- **语言**：Python 3（标准库 `urllib` 调用模型，**零第三方依赖**，离线可跑；仅 Streamlit 界面需 `streamlit`）
- **模型**：本地 Ollama，`buding-qwen05b-32k`（0.5B，离线、免 Key）；亦可在 `.env` 切换为百炼/OpenAI 兼容端点
- **界面**：Streamlit（`app.py`）；终端（`cli.py`）；独立动画版 HTML+Canvas（`wheel.html`，双击即开、离线可用）
- **数据源**：`data/food_data.json`（菜品示例）、`data/shops.json`+`data/campus.json`（周边商户示例+校区真实经纬度）、`data/profile.json`（记忆画像）、`data/history.json`（选择历史）

## 五、环境要求与运行

### 1. 安装并启动本地模型（只需一次）
```powershell
winget install Ollama.Ollama
ollama pull buding-qwen05b-32k
ollama serve        # 默认监听 http://localhost:11434
```

### 2. 运行 Streamlit 界面（推荐演示入口）
```powershell
cd <项目目录>
pip install -r requirements.txt
python -m streamlit run app.py
# 浏览器打开 http://localhost:8501
```

### 3. 运行终端演示（备用）
```powershell
python cli.py
```

### 4. 独立动画版大转盘（最直观，双击即开）
直接用浏览器打开 `wheel.html` 即可，无需启动任何服务；左侧切「📍 就近推荐」可体验校区定位+距离+评分推荐。可选联网调用本地 Ollama 生成一句“勾食欲”解说。

### 5. 切换为联网大模型（可选）
复制 `.env.example` 为 `.env`，修改 `OLLAMA_MODEL` 为百炼/OpenAI 兼容模型，并设置 `OPENAI_API_KEY` 与 `BASE_URL`。

## 六、演示话术（上台参考）

1. **开场**：“很多同学都有选择困难，今天我做一个专门帮大家做吃饭决策的智能体——它不仅会转转盘，还**记得你、会定位、能给性价比方案**。”
2. **记忆画像**：“先说‘我在金海校区，预算20，不吃辣’——它记下了，下次推荐自动套用。”（侧边栏可见画像）
3. **触发转盘**：“不知道今天吃啥，帮我选选。” → 模型调用 `build_wheel(where)`，弹出第一层转盘 → 转/接受 → 口味「不辣」→ 菜品转盘（可设金额上限≤20）→ 拒绝「麻辣香锅」→ 剔重转 → 接受「番茄炒蛋」→ 美食名片 → 确定。
4. **就近推荐**：“金海校区附近便宜好吃的，预算20。” → `recommend_nearby_food` 以校区为圆心，按距离+性价比+评分排序，列出店名/距离/花销/评分，🏆 标出最佳性价比。
5. **近期画像**：“它还会记我每次的选择，最近10次能看出我的口味习惯。”（侧边栏“选择历史 / 近期画像”）
6. **危险操作**：“发给室友” → 弹出**确认**框（不确认不执行）。
7. **收尾**：“这是一个有记忆、能定位、会推荐的专精型智能体：真实 Tool Calling + 可交互转盘 + 就近性价比 + 记忆画像。”

## 七、数据说明（如何从“示例”变“真实”）

- `data/food_data.json`：菜品示例，字段（name,price,canteen,window,tags,desc）与真实食堂一致，替换即真实数据源。
- `data/shops.json` + `data/campus.json`：周边商户示例；距离为代码按校区真实经纬度**实时计算**（非写死）。把 `shops` 换成杉达周边真实商户（保留 lat/lng 字段）即真实可用。
- `data/profile.json` / `data/history.json`：用户本地记忆，已加入 `.gitignore`，不进仓库。

> 关于“假数据”的说明：智能体的价值永远来自背后的真实系统。本作业按课程“路径 B 允许模拟后端”的约定，使用标注清楚的示例数据演示完整工具调用与设计；架构已为接入真实数据源预留（替换 JSON 即可），符合工程实践。

## 九、局限与改进

- 当前菜品/商户数据为示例；接入杉达真实菜单与周边真实商户后实用性更强。
- 0.5B 本地模型在“多级工具链”上偶有不稳定的情况，演示时由界面状态机保证每一层转盘都正确（LLM 负责理解与开场触发+解说）。可换更大模型进一步提升自主链式调用能力。
- 后续可扩展更多决策场景（去哪自习、周末去哪玩），复用同一套转盘/推荐/记忆机制。
