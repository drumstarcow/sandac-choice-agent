# 🍱 吃饱饱助手 · 帮我决定今天吃啥（校园决策智能体）

> **开源创新微专业 · 期末考查（路径 B：校园服务智能体）**
> 一个专门帮“选择困难”的大学生做吃饭决策的智能体：**自然语言理解 → 真实 Tool Calling → 决策大转盘 / 就近性价比推荐 → 记忆画像 → 确定产出**。

---

## 一、项目简介

很多大学生都有“选择困难”：站在食堂门口不知道吃啥、想吃点辣又怕踩雷、想出去吃又不知道附近哪家性价比高。本项目把“**帮大学生做选择**”作为智能体的核心价值，做成两路能力：

**能力一 · 决策大转盘**（不知道吃啥、想玩一下时用）
- **第一层 · 在哪吃**：食堂 / 外卖 / 外面吃
- **第二层 · 口味**：辣 / 不辣 / **随便**（无所谓就选它，第三层不过滤）
- **第三层 · 菜品**：按口味过滤；转盘可设**金额上限**；随机转到不想要的 → **拒绝** → 该选项权重清零、其余按权重重排（**扇区实时显示概率%，拒绝后重排肉眼可见**）；转盘正中「转一下」是**真实可点按钮**
- **确定前 · 美食名片**：弹出特写+介绍的卡片勾起食欲；不喜欢可「换一个」重转
- **确定后**：生成「今日决定」产出物（Markdown），可一键发给室友（**危险操作，需确认**）

**能力二 · 就近综合推荐**（心里已有想法、要“直接给方案”时用）
- 以你定位的**校区为圆心**（如「上海杉达金海校区」），用 haversine **真实算距离**
- 按 **距离 + 性价比 + 评分** 加权排序，给出就近美食清单
- 显示：**店名 / 位置 / 距离 / 预估花销 / 评分 / 综合分**，可切换「性价比综合 / 就近优先 / 好评优先」
- 转盘上可设**金额上限 / 不限**；用户不想转盘时直接给**最佳性价比方案**

**记忆能力（智能体的“牙齿”）**
- **用户记忆画像**（`data/profile.json`，本地持久化）：记住校区(定位圆心)/金额上限/口味偏好/忌口/饮食限制，跨轮套用
- **选择历史 + 近期画像**：每次完成选择都留痕（`data/history.json`）；最近 10 次聚合出“近期画像”（最常去校区/场景/口味、最爱菜或店、平均预算与花销）——用户可查看历史、删除不想要的

> 设计要点：不是“啥都答的豆包”，而是**专精于“吃饭决策”这一个领域**；转盘与推荐都来自真实数据+真实计算，被拒绝后概率均分重排、距离用球面公式实时算——是真实的“决策辅助”，不是关键词 if-else。

## 五、环境要求与运行

### 0. 最快方式：双击就能跑（不用命令行）

在项目文件夹里直接双击：

| 文件 | 作用 |
|---|---|
| **`3-网页版对话.bat`** | **推荐**。起网页版对话界面并自动打开浏览器（好看、可点、可截图） |
| **`1-自动演示.bat`** | 自动跑完一整段终端对话，无需任何输入（上台演示/录屏用） |
| **`2-自己对话.bat`** | 终端交互模式，自己打字跟智能体聊 |

脚本会自动：切到项目目录 → 设好 UTF-8 编码 → 自动探测可用的 Python 解释器 → 检查本地模型服务是否在跑（没跑就自动拉起 Ollama）→ 启动 → 结束后暂停窗口不闪退。

> 说明①：`.bat` 里只写英文，中文提示由 `banner.py` 用 Python 打印。因为 cmd 会按系统代码页（GBK）读取 `.bat`，里面直接写 UTF-8 中文会乱码甚至截断命令行。
>
> 说明②：启动器不依赖 PATH 里的 `python`（Windows 上它常指向微软商店占位符），会按 `py -3` → `Python314/313/312` 安装目录 → 内置运行时的顺序自动探测，并把选中的解释器打印在 `[2/2]` 行。

### 0.1 网页版对话（`webchat.py` + `web/`）


## 六、演示话术（上台参考）

1. **开场**：“很多同学都有选择困难，今天我做一个专门帮大家做吃饭决策的智能体——它不仅会转转盘，还**记得你、会定位、能给性价比方案**。”
2. **记忆画像**：“先说‘我在金海校区，预算20，不吃辣’——它先回显‘要记住你不吃辣，对吗？’（二次确认），确认后才写入长期记忆，下次推荐自动套用。”（侧边栏可见画像 + 工具调用过程面板可见 `save_preference`）
3. **触发转盘**：“不知道今天吃啥，帮我选选。” → 模型调用 `build_wheel(where)`，弹出第一层转盘 → 点正中「转一下」→ 接受 → 口味「不辣」→ 菜品转盘（可设金额上限≤20）→ 拒绝「麻辣香锅」→ **它明说“这个你拒过了，不会再推给你”，扇区概率同步重排** → 接受「番茄炒蛋」→ 美食名片 → 确定。
4. **就近推荐**：“金海校区附近便宜好吃的，预算20。” → `recommend_nearby_food` 以校区为圆心，按距离+性价比+评分排序，列出店名/距离/花销/评分，🏆 标出最佳性价比。
5. **近期画像**：“它还会记我每次的选择，最近10次能看出我的口味习惯。”（侧边栏“选择历史 / 近期画像”）
6. **危险操作**：“发给室友” → 弹出**确认**框（不确认不执行）。
7. **收尾**：“这是一个有记忆、能定位、会推荐的专精型智能体：真实 Tool Calling + 可交互转盘 + 就近性价比 + 记忆画像。”

## 九、转盘概率模型与挑刺测试清单（设计验收）

> 本节对应两份设计规格：《吃饱饱转盘设计建议》《吃饱饱对话层与挑刺测试建议》。核心目标：让评审 30 秒内判断“这不是关键词 if-else”。

### 9.1 三层结构与铁律
- L1 在哪吃 → L2 口味 → L3 菜品；**任一被拒，下游立即重算**（菜品池随口味/预算重过滤，不会“拒了 A 食堂又从 B 食堂转出 A 的招牌菜”）。
- 拒绝采用「权重清零」而非「重新随机」：被拒项本会话权重 = 0 永不复活，其余归一化重排——这是区分“真随机”与“伪随机”的关键。

### 9.2 权重概率模型（真实代码，非提示词 if-else）
- 抽中后衰减：`w *= 0.6`，避免连着抽同一个；
- 被拒绝：`w = 0`（本会话内，直到新会话/重置）；
- 归一化：每次抽取前 `p_i = w_i / Σw`，**扇区上直接显示该 %**；
- 空态兜底：三层全拒完 → 不空转，把选择权交回用户。

### 9.3 Tool Calling 契约（模型真实调用，日志可见）
- 业务工具：`build_wheel` / `recommend_nearby_food` / `finalize_decision` / `finalize_recommend` / `get_profile` / `set_profile` / `get_recent_profile`；
- 危险写操作：`save_preference`（写入长期记忆）与 `share_with_roommate`（对外发送）**必须经用户确认才执行**（可审计、可撤销）；
- 每次调用都显示在界面「🔧 工具调用过程」面板，日志里能看到 `tool_call`。

### 9.4 对话人格与意图
饭友人设：简短、直接、不谄媚、不写客服腔；五类意图（明确指令 / 模糊表达 / 设限 / 拒绝 / 无关话题）分别处理；遇到无关话题（如“今天好累”）接一句人话，**不硬拽回转盘**。

### 9.5 挑刺测试清单（交前逐条跑）
**A. 假 AI 探测**
1. “我不吃辣” → 转一次 → “刚才说的你还记得吗？”（应答得出）
2. “今天好累” → 是否硬拽回转盘（应像人一样接一句）
3. “你能帮我写作业吗？” → 是否胡诌（应说“这个我不擅长”）

**B. 拒绝逻辑**
4. 连续拒同一个三次 → 还会出现吗（不会）
5. 只剩两个候选 → 拒一个 → 概率有没有变（有）
6. 全拒完 → 是否空转盘（应“换个路子？”）

**C. 空态**
7. 无匹配 / 食堂全关 → 是否说清楚而非白屏（给出降级 / 放宽建议）
8. 关键词无匹配 → 降级为综合推荐并说明

**D. 边界与责任**
9. 保存偏好有没有二次确认（有：回显“要记住：xxx，对吗？”）
10. 说“随便”时有没有给理由（给出，而非白给一个）

**E. 断话乱说**
11. 空输入 / 标点 / 半句“我想吃…” → 会不会卡死（兜底不卡）
12. 同一句问两遍 → 答案一致或有理由地变

### 9.6 演示里最值钱的三句话
1. “**这个你已经拒过了，我不会再推给你。**”（证明权重真的在变）
2. “**今天好累啊……那来点热的？**”（证明不是只会转盘）
3. “**要记住你不吃辣，对吗？**”（证明写操作有确认）

## 十、局限与改进

- 当前菜品/商户数据为示例；接入杉达真实菜单与周边真实商户后实用性更强。
- 0.5B 本地模型在“多级工具链”上偶有不稳定的情况，演示时由界面状态机保证每一层转盘都正确（LLM 负责理解与开场触发+解说）。可换更大模型进一步提升自主链式调用能力。
- 后续可扩展更多决策场景（去哪自习、周末去哪玩），复用同一套转盘/推荐/记忆机制。
