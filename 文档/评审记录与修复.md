## 二、问题 1：emoji 判断工具调用（已修复）

**位置**：`legacy/webchat.py`，两处，均在归档的旧网页版后端里。

```python
# 第 240 行附近：从步骤文本反推工具调用
if t.startswith("🔧 调用 "):
    body = t[len("🔧 调用 "):]

# 第 316 行附近：据此决定要不要兜底
```

## 三、问题 2：FALLBACK 是否只在异常分支（已审计）

`_fallback()` 全项目只有 **2 个调用入口**，其余十余处 `fallback=True` 只是 `_msg()` 的**打标参数**，不是新入口。

| 入口 | 位置 | 触发条件 | 性质 |
|---|---|---|---|
| 1 | `server.py` `act_chat()` | `agent.chat()` 抛异常，或返回 `status=error` | 纯 `except` 分支 |
| 2 | `server.py` `act_chat()` | `tool_calls == 0` **且** `content` 为空（模型完全空返回） | 异常输入守卫，非正常路径 |

正常对话一定满足「有 content 或 有 tool_calls」之一，两者同时为空只能是模型故障。为便于对账，兜底 `reason` 已带上现场参数：

```
[FALLBACK] reason=模型返回空（status=done tool_calls=0 content=0）
```

**结论：没有正常路径会悄悄走兜底。**

## 四、问题 3（评审未提，自查发现）：模型调用缺日志

原 `[TOOL]` 日志只覆盖**编排层**发起的工具调用，模型自己调用的工具反而没有日志——这恰恰是「假 AI」最容易被质疑的地方。

**修复**：统一加 `source` 来源标记。

| 日志 | 含义 |
|---|---|
| `[TOOL] source=model ...` | 模型自主决定调用（答辩重点看这个） |
| `[TOOL] source=orchestrator ...` | 界面操作触发（点某层转盘、确认、收尾） |
| `[TOOL] source=fallback ...` | 模型异常后的兜底执行，仍真实调用工具 |

**实测输出**：

```
# 用户输入「想吃火锅」
[TOOL] source=model tool_calls=1 layer=recommend name=search_dish
[CHAT] tool_calls=1 status=recommend content_len=0

# 人为触发兜底
[FALLBACK] reason=单元测试：模拟模型异常
[TOOL] source=fallback tool_calls=1 layer=meal name=build_wheel
```

## 五、问题 4（演示时暴露）：窗口打开是 404

**现象**：双击启动后控制台一切正常（模型、地址、窗口都对），Edge 窗口却显示「错误响应 / 文件未找到」。

**根因**：Windows 的 `SO_REUSEADDR` 允许两个进程绑定同一端口，先监听者收包。上次没关干净的旧进程占着 8770，新进程「绑定成功」却永远收不到请求，浏览器连到的是旧进程。

**修复**：

1. `server.py` 关闭地址复用，改用 `SO_EXCLUSIVEADDRUSE`，端口被占直接报错；
2. `app.py` 找端口改为「先探测能否连上 → 再独占真绑一次」；
3. 起服务后主动请求 `/`，校验返回页面含「吃饱饱」，不是自己的就换下一个端口；
4. 控制台明确提示：`⚠ 端口 8770 已被其它程序占用，改用 8771`。

## 六、问题 5（截图暴露）：四条并列出现重复

**现象**：候选池只有 2 家火锅店时，「综合最佳」和「最便宜」展示了同一道菜。

**根因**：`finalize()` 在凑不满 4 条时用重复项补齐。

**修复**：宁缺勿重——不足 4 个不同选项就只给实际条数，并说明原因：

```
符合条件的就这 2 条，挑一个
「火锅」相关共 2 条，不重复的都在这儿了，没拿重复的凑数
```
