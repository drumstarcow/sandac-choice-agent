## 二、问题 1：emoji 判断工具调用（已修复）

**位置**：`legacy/webchat.py`，两处，均在归档的旧网页版后端里。

```python
# 第 240 行附近：从步骤文本反推工具调用
if t.startswith("🔧 调用 "):
    body = t[len("🔧 调用 "):]

# 第 316 行附近：据此决定要不要兜底
no_tool = not any(isinstance(x, str) and "🔧" in x for x in steps)
```

**根因**：`agent.chat()` 早已返回结构化 `calls=[{name, args, result}]`，旧代码却退回去解析字符串；模型只要不按这个格式吐字，就会被误判成「没调工具」。

**修复**：

```python
def build_tools(calls, steps=None):
    """直接消费结构化 calls，只搬字段，不做文本猜测。"""
    for c in calls or []:
        out.append({"name": c["name"], "args": c["args"], "result": res[:800]})

# 兜底判定同样改为看结构
if not calls and not s.wheel and not s.finalized:
```

同时清理全部**显示用途**的同类字符（控制台、幻灯片、UI 图标改为 `[工具]` 文案与 CSS 方块），避免下一轮 `grep` 再被误判。

**验证**：

```

```

## 三、问题 2：FALLBACK 是否只在异常分支（已审计）

`_fallback()` 全项目只有 **2 个调用入口**，其余十余处 `fallback=True` 只是 `_msg()` 的**打标参数**，不是新入口。

| 入口 | 位置 | 触发条件 | 性质 |
|---|---|---|---|
| 1 | `server.py` `act_chat()` | `agent.chat()` 抛异常，或返回 `status=error` | 纯 `except` 分支 |
| 2 | `server.py` `act_chat()` | `tool_calls == 0` **且** `content` 为空（模型完全空返回） | 异常输入守卫，非正常路径 |

正常对话一定满足「有 content 或 有 tool_calls」之一，两者同时为空只能是模型故障。为便于对账，兜底 `reason` 已带上现场参数：

```
[FALLBACK] reason=模型返回空（status=done tool_calls=0 content=0）
```

**结论：没有正常路径会悄悄走兜底。**

## 四、问题 3（评审未提，自查发现）：模型调用缺日志

原 `[TOOL]` 日志只覆盖**编排层**发起的工具调用，模型自己调用的工具反而没有日志——这恰恰是「假 AI」最容易被质疑的地方。

**修复**：统一加 `source` 来源标记。

| 日志 | 含义 |
|---|---|
| `[TOOL] source=model ...` | 模型自主决定调用（答辩重点看这个） |
| `[TOOL] source=orchestrator ...` | 界面操作触发（点某层转盘、确认、收尾） |
| `[TOOL] source=fallback ...` | 模型异常后的兜底执行，仍真实调用工具 |

**实测输出**：

```
# 用户输入「想吃火锅」
[TOOL] source=model tool_calls=1 layer=recommend name=search_dish
[CHAT] tool_calls=1 status=recommend content_len=0

# 人为触发兜底
[FALLBACK] reason=单元测试：模拟模型异常
[TOOL] source=fallback tool_calls=1 layer=meal name=build_wheel
```

## 五、问题 4（演示时暴露）：窗口打开是 404

**现象**：双击启动后控制台一切正常（模型、地址、窗口都对），Edge 窗口却显示「错误响应 / 文件未找到」。

**根因**：Windows 的 `SO_REUSEADDR` 允许两个进程绑定同一端口，先监听者收包。上次没关干净的旧进程占着 8770，新进程「绑定成功」却永远收不到请求，浏览器连到的是旧进程。

**修复**：

1. `server.py` 关闭地址复用，改用 `SO_EXCLUSIVEADDRUSE`，端口被占直接报错；
2. `app.py` 找端口改为「先探测能否连上 → 再独占真绑一次」；
3. 起服务后主动请求 `/`，校验返回页面含「吃饱饱」，不是自己的就换下一个端口；
4. 控制台明确提示：`⚠ 端口 8770 已被其它程序占用，改用 8771`。

## 九、第二轮复看（10-31 晚）

### 9.1 转盘转完看不到「多条方案」

**现象**：一键演示从转盘直接往收尾走，四条只闪一下。

**根因**：演示脚本接受菜品后只 `sleep(1600)` 就调 `finalize`，四条刚画出来就被收尾卡片覆盖。

**修复**：

- 演示在第 7 步停 **5.2 秒**，并往聊天里写一句「右边现在 = 名片 + 4 条并列方案（综合最佳/最近/最便宜/评分最高）」，让「转盘 → 多条方案」这一步看得见；
- 名片页标题下加一行「同一条件下另有 N 条备选，往下滑就是四条并排对比」，避免只看见一张卡；
- 截图索引新增 `14-演示停在四条方案.png` 作为证据。

（手动流程本来就正常：接菜后 `step=card`，`renderStage` 会画名片 + 四条。已用 `?auto=card` 排练钩子实测：DOM 里 4 个 `.pick`。）

### 9.2 「随便」放在扇区上是逻辑冗余

**现象（用户提出）**：餐别层是「正餐 / 甜品饮料 / 随便」三扇区。拒掉「正餐」后只剩「甜品饮料」和「随便」，而「随便」≡ 两个都行，等于只剩一个真选项，转盘没有悬念。

**根因**：「都行」是元选项，不该和互斥的真实选项混在同一张概率盘上。

**修复**（`tools.build_wheel` / `ui/app.js`）：

- 扇区只放互斥的真实选项：餐别 `正餐 / 甜品饮料`，口味 `辣 / 不辣`；
- 「随便」改成盘外按钮「都行，你替我定」，点击即该层各 50% 掷一次（`accept(key="随便")` 兼容原有逻辑），不参与概率抽取；
- 拒到只剩一个选项时：中心按钮变「只剩一个」、概率 100%、「换一个（拒绝）」置灰，并提示「这层只剩 X 了，没得转，直接定就行」——不再让人把最后一层也拒空；
- 同理去掉「外卖」扇区：数据里周边店铺堂食/外卖是同一批，单开一个扇区等于假选项（`where_options` 只留 `食堂 / 外面吃`；口头说「点外卖」仍按外面吃这一档过滤）。

### 9.3 顺手修掉的小问题

- 名片／收尾阶段面包屑整排变灰：`state_payload` 补 `choices`，`crumbs()` 优先读 `st.choices`（原来只从已销毁的转盘视图里取）；
- 新增排练钩子 `?auto=card`：不做动画直接跳到「名片 + 四条」，方便答辩前定位与排查。

## 十一、第三轮：四层改五层 + 隐藏款（10-31 晚）

用户三条反馈：①「格子层转不动就多加几层细分开来，按不同菜系」；
②「第一层有问题，应该分为食堂、出去吃、外卖和一个额外选项（随便）」；
③「格子不够就重新排版，力求所有选项都要有，随机大转盘最重要的就是随机，所有选项都要有；
重口猎奇区作为隐藏款，只有前面几层都选了随机才会出现在选项内」。

### 11.1 四层 → 五层

原链条 `meal → where → spice → dish` 变成 `meal → where → spice → cuisine → dish`。

新增的**菜系层**由后端按当前候选的**真实分布**统计生成（不是写死的固定列表），
数量多的排前面、同数量按固定顺序：

| 场景 | 菜系层的实际输出（示例） |
|---|---|
| 食堂 + 辣 | 风味小炒 8 / 清淡素菜 4 / 家常小炒 3 / 快餐简餐 3 |
| 外面吃 + 辣 | 烧烤烤肉 15 / 火锅 13 / 川湘辣菜 8 / 快餐简餐 5 / 面食粉面 4 |
| 外面吃 + 不辣 | 小吃早餐 8 / 快餐简餐 3 / 火锅 3 / 家常小炒 2 / 面食粉面 2 / 西餐日韩 2 |
| 甜品 + 外面吃 | 奶茶 14 / 咖啡 11 / 甜点烘焙 9 |

食堂炒菜在数据层按窗口拆成三类：第一食堂大众窗口的素菜 → `清淡素菜`，
同窗口的荤菜 → `家常小炒`，第二食堂风味窗口 → `风味小炒`。
不拆的话「家常小炒」一类 40 道，格子层又转不动了。

### 11.2 格子层不再截断（这条最关键）

上一轮为了「转得动」，格子层封顶 24 个、按评分取前 24 —— 等于**每转一次就偷偷丢掉 80% 的候选**，
「随机」名存实亡。用户指出后改成：

- `GRID_CAP = 0`（不截断），菜系层已经把每类压到 3–21 个；
- 格子用 `grid-template-columns: repeat(auto-fill, minmax(112px, 1fr))` 自动换行，多了就滚动；
- 跳格动画的跳数从固定 28 改成 `max(28, min(44, 格数 + 12))`，格子多了也真的绕完整盘。

### 11.3 场景层四个真选项 + 外卖不再是假选项

上一轮把「外卖」删了，理由是「和外面吃是同一批店」。这一轮加回来，但给了**真的区分依据**：

- 数据层给每家店加 `delivery`：火锅、烧烤这类到店现做现吃的不送外卖；校内食堂窗口不送；
- 候选池从「单一 where 字段」改成 `channels` 列表，一家店可以同时属于「外面吃」和「外卖」；
- 结果：食堂 69 / 外面吃 67 / 外卖 37 / 随便 136，四个扇区数量各不相同，图例直接标出来。

「随便」在场景层是**真扇区**（= 不限场景），因为此时有三个互斥真选项，它不会退化成冗余；
真选项被拒到只剩一个时，「随便」会自动撤下并说明原因（`act_reject` 里的 `real <= 1` 分支）。

### 11.4 隐藏款「重口猎奇」

- 只收录**当前条件下评分垫底 9 个**（先按全部条件筛完，再按评分升序 + 距离降序取）；
- **解锁条件**：餐别 / 场景 / 口味三层都被用户主动选了「随便」（`Session.rnd` 三个标记全为真）；
- 甜品饮料没有口味层，等价于「口味也交给了命运」，所以甜品路径同样可解锁；
- 解锁时菜系层标题下直接写「🌈 前三层你都选了「随便」，隐藏款「重口猎奇」已解锁」。

### 11.5 顺带修的

- **重名菜看不出区别**：三家店都叫「烤串」、两家都叫「老火锅」。现在格子层统计同名数量，
  只在**重名时**多显示一行店名（不重名不显示，避免食堂一整窗都写「第二食堂·风味窗口」的噪音）；
- **扇区多了字压边**：11 个扇区时 15px 字号会顶到扇区边界，改成 `n>=10 → 12px`、`n>=8 → 13px`；
- **菜系层说明文字没显示**：`renderWheel` 原来只画 `ctx` 不画 `note`，隐藏款解锁了也看不见，
  现在两行都显示；
- **「只有一道菜」的菜系也不剔除**：否则那道菜永远转不到，违背「所有选项都要有」；
  只有整组候选 ≤6 个时才跳过菜系层（再分下去纯属折腾）；
- **一键演示 8 步 → 9 步**（多了菜系层），第 8 步仍停 5 秒看四条。

## 十二、第四轮：场景层「随便」移出盘外 + 层级直达（10-31 夜）

### 12.1 场景层「随便」也是冗余的（用户提出）

> 「在第二层场景中，随便这个选项应该出现在外面，和第一层一样」

上一轮把「随便」当成场景层的真扇区，理由是「它代表不限场景，语义独立」。用户不认：
他站在第二层，看到 4 个扇区里有 1 个「随便」，拒掉「食堂」之后剩下「外面吃 / 外卖 / 随便」，
「随便」还是那句和稀泥的话 —— 判据不是「它有没有独立语义」，而是**它能不能被抽中**。
「随便」不是结果，是「这层我不要了」的操作，三种层都一样。

- `build_wheel("where")` 只输出三个真扇区：食堂 / 外面吃 / 外卖；
- 「随便」改走 `skip = {"key": "随便", "label": "哪都行，你替我定"}`，渲染成盘外按钮，和第一层同一个位置、同一种样式；
- 删掉 `act_reject` 里「场景层拒到只剩一个就把随便撤下」的特判 —— 不在盘上，就没有撤下一说；
- `counts` 里也不再混入「随便 136」，图例只剩三个真数（69 / 67 / 37）。

### 12.2 想直接去某一层，就把它调出来（用户提出）

> 「如果用户就想去特定的那个转盘呢，应该能直接调用出来」

- 后端新增 `act_jump(scene)` + `POST /api/jump`：清掉本层及其之后的选择，缺失的上层上下文补成
  「正餐 / 不限场景 / 不限口味」，再照常真实调用 `tools.build_wheel` —— 盘上的候选、概率、四条推荐仍是同一套数据；
- 前端面包屑从「只读标签」变成**层级导航**：五格都是按钮，点哪层跳哪层，当前层描边高亮，
  前面加了「点任意一层可直达」的提示；
- 对话也能直达：提示词里补了规则，用户说「直接看菜系 / 跳到菜品」时模型直接 `build_wheel(scene=那一层)`，
  服务端在 `act_chat` 收到跨层转盘时自动补齐 `choices`，并把原来那句「交给命运」换成「行，跳过前面几层，直接看「菜系」」；
- 调试钩子扩到 `?auto=meal|where|spice|cuisine|dish`，排练/截图可直接落到指定层。

### 12.3 顺带修的

- **「开始转盘」不清残留**：玩到一半再点开始，面包屑还挂着上一轮的场景和菜系。`act_build_meal` 现在等于开新一轮（清 `choices`/`rnd`/`rejected`，重置 `WheelEngine`）；
- **收尾卡片写「在哪：随便」**：场景选了「随便」时，用这道菜真实的归属（`item.where`）兜底成食堂/外面吃；
- 口味层的「上一层：随便」不再显示（`ctx` 过滤），省得一句话看着莫名其妙。
